# 007 在庫の更新と要確認レビュー

- 状態：合意済み
- 依存：006

## 👤 ユーザーが確認するところ

### 何のための機能か
買ったとき・使ったとき・入れ替えたときに在庫を直せるようにします。また、写真から仮登録した明細を家族が確認して直せるようにします。

### できるようになること
（すべてオンラインのときだけ。保存に成功したときだけ「保存しました」と出す）

**在庫の操作**
- **追加**：品名、数量、単位、カテゴリ、保管場所、期限（年月日／年月／なし）、期限の種類（賞味期限／使用・点検期限／種類不明）、期限の確認状況、管理の状態、メモ、水なら1本あたりのリットル、非常用トイレなら公称の使用回数。
- **数量を増やす・減らす**：＋／－ボタンと数値入力。
- **期限を変える**：年月日・年月・なしを選んで入力。年月だけなら年月のまま保存する。
- **製造年月と「製造から○年」を入れる**：期限が印字されていない品のために、製造年月（または製造年月日）と年数を入力する。年数は、よく使う候補をボタンで選べる（最初の候補は「カセットガス：製造から7年」。家で一度使った年数も同じ品名の候補に出る）。候補はあくまで目安なので、品のラベルや説明書と違うときは数字を直接入れる。入力すると、計算された期限がその場で表示される。
- **保管場所を移す**：全部移すか、一部だけ移すか（一部なら、移した分が別の明細になる）。
- **消費・廃棄**：使った数・捨てた数を入れる。残りが 0 になったら通常の一覧から消える（記録は残る）。期限が過ぎただけでは消えない。
- **買い替え**：古い明細を「消費」または「廃棄」で外し、新しい期限の明細を追加する、を1回の操作で行う。期限が違う新しい品は、元の明細に足さず別の明細になる。
- **分ける**：セット商品を開けたときなどに、元の明細の数を減らし、中身を別の明細として登録する（確認画面あり）。
- **管理の状態・メモ・要確認の印を変える**：期限の状態を見て管理の状態を自動で書き換えることはしない。
- 同じ明細を2人がほぼ同時に変えた場合は、あとから保存した人に「ほかの家族が先に変更しました。最新を読み込んでからやり直してください」と出し、上書きしない。
- 購入予定の品は在庫に足さない（メモに書いておく）。

**保管場所の編集**
- 名前と説明（階・棚など）を変えられる。新しい保管場所を追加できる。中身が空の保管場所は削除できる。

**要確認の一覧**
- 「要確認」の印が付いた明細（写真からの仮登録など）を一覧で表示する。保管場所ごとに並ぶ。
- 1件ずつ開いて、品名・数量・種類などを直し、「確認済みにする」を押すと印が外れ、出どころが「確認済み」になる。直した内容はメモにも残せる。

### 使い方の流れ
1. 在庫一覧や明細から品物を開き、操作ボタン（数量・移動・消費・買い替え など）を押す。
2. 入力して保存 →「保存しました」と出て、この端末の保存分も新しくなる（005）。
3. 要確認タブで、写真からの仮登録を1件ずつ実物と見比べて直す。

### やらないこと
- オフライン中の編集。
- バーコード・QR の読み取り、レシートや写真からの自動入力。
- 購入候補リスト、最低在庫量の設定。将来の拡張。
- 写真の登録。将来の拡張。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 「製造から○年」は明細ごとに入力し、よく使う年数を候補として選べるようにする | 品ごとに年数が違っても対応でき、毎回調べなくて済むため（ユーザー回答） |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの（009 の実機確認にまとめて記載）：
  - 要確認の明細を、実物と見比べて直す（実物を見られるのは家族だけのため。アプリの完成を待たずにいつでもよい）

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：家族A（コンテキスト1）が明細を追加し、家族B（コンテキスト2）が同期すると、数量・保管場所・期限が一致する（自動テスト：Playwright＋疑似クラウド）
- [ ] AC2：消費で数量が 0 になった明細は一覧・検索・保管場所から消え、疑似クラウドのイベントに記録が残る（自動テスト）
- [ ] AC3：期限入力で「年月」を選ぶと `YYYY-MM`／precision=month で保存され、日付が補完されない（自動テスト）
- [ ] AC4：一部移動で、元の明細の数量が減り、移動先に同じ品名・期限の新しい明細ができる（自動テスト）
- [ ] AC5：買い替えで旧明細がアーカイブされ、新明細が追加される。途中で失敗したらどちらも反映されない（自動テスト：PGlite で RPC の原子性）
- [ ] AC6：分けるで、親の数量が減り、子の明細ができる。親の数量を超える分割はエラー（自動テスト）
- [ ] AC7：オフライン時は操作ボタンが無効で、通信中に切断されたら「保存できませんでした」と出し、「保存しました」を出さない（自動テスト）
- [ ] AC8：古い `updated_at` での更新は拒否され、競合メッセージが出る（自動テスト：PGlite＋Playwright）
- [ ] AC9：要確認一覧に `needs_review=true` の明細だけが出て、確認済みにすると消え、`source` が `photo_review` なら `user_confirmed` になる（自動テスト）
- [ ] AC10：保管場所の名前・説明の編集、追加、空の場所の削除ができ、中身がある場所は削除できない（自動テスト）
- [ ] AC12：製造年月と年数を入れると計算した期限がフォーム上に表示され、保存後の明細・一覧・期限の状態に反映される。候補ボタン「カセットガス：製造から7年」で 7 年（84か月）が入る。同じ品名の既存明細で使った年数が候補に出る（自動テスト）
- [ ] AC11：負の数量、空の品名、存在しない日付はフォームで止まり、送信されない（自動テスト）

### 設計方針
- フォームは自前のコンポーネント（React の制御コンポーネント＋002 の zod スキーマで検証）。
- 各操作は 001 の RPC に1対1で対応させ、`Backend.applyChange({type, ...})` に集約。疑似クラウドも同じ操作を実装し、同じ検証ロジック（`src/domain/changes.ts`）を使う。
- 成功時：トースト「保存しました」→ 再取得 → ローカル保存（005）。失敗時：エラー種別（オフライン・競合・検証・権限・その他）ごとの文言。
- 確認ダイアログ：消費・廃棄・買い替え・分ける・保管場所の削除。
- 期限入力 UI：種類（年月日／年月／なし）のラジオ＋`<input type="date">` または `<input type="month">`。製造年月も同じ部品を使う。
- 年数の候補：固定の候補 `src/domain/shelfLifePresets.ts`（`{label: 'カセットガス', months: 84}`）＋スナップショット中の同じ品名（正規化後）の明細で使われている `shelf_life_months`。候補を選んでも値は明細ごとに保存する（ルール表は持たない）。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 楽観的 UI 更新（保存前に画面へ反映） | 不採用 | 保存できていないのに成功に見える（BRIEF 6.1） |
| 買い替え時に元の明細の期限だけ書き換える | 不採用 | 期限の違う新ロットは別明細（BRIEF 4.4） |

### 検証方法
- 自動テスト：Vitest（変更の検証）、PGlite（RPC の原子性・楽観ロック）、Playwright（2コンテキスト同期、オフライン、フォーム）。
