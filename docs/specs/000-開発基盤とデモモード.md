## 👤 ユーザーが確認するところ

### 何のための機能か
アプリを作り始めるための土台です。クラウドの準備ができる前から、パソコンの中だけでアプリを動かして試せるようにします。

### できるようになること
- このパソコンでアプリを起動して、ブラウザで画面を確認できる。
- クラウド（Supabase）に接続しなくても、**架空の見本データ**で全画面を試せる「デモモード」がある。デモモードは開発中のパソコンの中だけで動き、公開するアプリには入らない。
- パソコンの中だけで、本物の初期データ（`data/` に置いたもの）をデモモードに読み込んで見た目を確かめられる。
- 本物の在庫データの置き場所は、**クラウドのデータベース（Supabase）と、ログインした家族の端末の中だけ**。公開リポジトリ（GitHub）にも、インターネットに置くアプリの本体（画面のプログラム）にも入れない。アプリはログインしたあとに Supabase から在庫を読み込む。
- テストを自動で実行できる。GitHub に置いたあとは、変更のたびに GitHub 上でもテストが自動で動く（公開リポジトリは無料）。

### 使い方の流れ
1. Claude がアプリの土台を作り、デモモードで起動できることを確かめる。
2. 以降の機能は、まずデモモードと自動テストで動きを確かめてから、本物のクラウドにつなぐ。

### やらないこと
- 既存の別プロジェクトのコードやデータベースの流用（新しく独立して作る）。
- 公開するアプリでデモモードを使えるようにすること。

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| コードは GitHub の公開リポジトリに置く。初期データ（家の備蓄の一覧）は Git に含めない | 記事などで公開できるようにしつつ、家の備蓄の中身は公開しないため |
| 自動テストは架空の見本データで行い、本物の初期データでの確認はこのパソコンの中だけで行う | 本物のデータを公開リポジトリに入れないため |

### 設計方針
- Vite + React + TypeScript。ルーティングは react-router（BrowserRouter。配信側は Workers の静的アセットの `not_found_handling: "single-page-application"` で index.html を返す。009）。
- スタイルは素の CSS（1枚のグローバル CSS `src/ui/styles.css`。画面数が少なく、CSS Modules にするほどの衝突がないため）。モバイルファースト、タップ領域 44px 以上。UI ライブラリは入れない（バンドルを小さく保ち、オフライン用プリキャッシュを軽くするため）。
- **データの出入り口を1つのインターフェースにまとめる**（`src/backend/types.ts` の `Backend`：`fetchSnapshot()`／`applyChange(change)`／`signIn`／`signOut`／`getSession`）。実装は2つ。
  - `SupabaseBackend`：本番。
  - `DemoBackend`：開発サーバー限定。Vite プラグイン（`configureServer`）で `/__demo_api/*` を提供し、メモリ上の「疑似クラウド」に読み書きする。複数のブラウザコンテキストが同じ疑似クラウドを共有するので、E2E で「家族A が追加 → 家族B が同期」を再現できる。`context.setOffline(true)` で通信も遮断できる。
  - どちらを使うかは `import.meta.env.DEV && VITE_DEMO=1` で決め、本番ビルドでは `DemoBackend` のコードが tree-shake で消えるようにする。
- 見本データ：`fixtures/sample-data.json`（`initial-data.json` と同じ形式の架空データ）。月単位の期限、同名で期限違いの在庫、セット商品の内訳、期限切れの水、買い替え予定、1年以内・日付未確認、問題なし報告、写真由来の要確認、リュック4個、ローリングストックを必ず含める。
- 実データでの確認：`data/checks/` に置く（gitignore）。Vitest と Playwright の設定で、このフォルダがあれば対象に含め、なければ飛ばす。BRIEF 9.1 の実データ項目（特定の品名・数量）はここに書く。
- `.gitignore` に `data/*`（`!data/README.md`）を追加。テンプレートの `config.toml` 無視ルールに対し `!supabase/config.toml` を追加（Supabase CLI の設定は秘密を含まないため）。
- `.env.example`：`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`、`VITE_DEMO`、`SUPABASE_SECRET_KEY`（シード・メンバー追加用。`VITE_` を付けない）、`DEMO_DATA`。
- CI：`.github/workflows/ci.yml`（Node 22、`npm ci`、lint、typecheck、Vitest、Playwright Chromium）。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| デモをブラウザ内だけの疑似データにする | 不採用 | 2端末の同期を E2E で再現できない |
| ローカル Supabase（Docker） | 不採用 | Docker が未導入で、デモモードと PGlite（001）で十分に検証できる |
| Tailwind / UI ライブラリ | 不採用 | 画面数が少なく、プリキャッシュを軽くしたい |
