# sonaelog

家庭の防災備蓄を「何が・どこに・いくつあり・いつ期限を迎えるか」で管理する PWA。
家族（大人2人がログイン）の Android スマホから、クラウド上の共通在庫を閲覧・更新する。
災害時にネットが使えなくても、事前に同期した端末だけで在庫を検索・閲覧できる。

## 設計の前提（なぜこの作りか）
- **クラウドが正本、端末はその写し。** 平時はクラウド（Supabase）の在庫を家族で共有し、各端末は「最後に読み取りに成功した完全な在庫」を丸ごと保存する。
- **オフラインは見るだけ。** 有事に必要なのは「探せること」。オフライン編集と後日の統合は、複雑さに見合わないのでやらない。
- **ログインが切れても見られる。** 端末に保存済みの在庫は、ネットやログインの状態に関係なく閲覧できる。その代わり、端末を操作できる人には在庫が見える（画面ロック前提。住所・健康情報などは入れない）。
- **分からないことは分からないまま表示する。** 期限が不明なものに日付を補わない、「年月」だけの期限に日を足さない、単位の違う数を足さない、写真からの仮登録は「要確認」のまま残す。
- **同じ品でも期限・場所が違えば別の在庫。** 勝手にまとめない。
- やらないこと：通知、バーコード読み取り、購入連携、避難判断、誰でも見られる共有ページ。

詳しい経緯は [docs/HISTORY.md](docs/HISTORY.md)、仕様は [docs/specs/](docs/specs/README.md)。

## 主な機能
- ホーム：オフラインで使えるか（保存済み・最終同期日時）、期限別の件数、水・食事・非常用トイレの「分かっている分だけ」の集計
- 在庫一覧：キーワード検索、カテゴリ・保管場所・管理の状態・期限の状態での絞り込み、並べ替え
- 保管場所：長期備蓄、家族ごとの持ち出しリュック、ローリングストックなどの場所別表示と説明の編集
- 在庫の更新：追加・数量変更・期限変更・移動・消費・廃棄・買い替え・分割（オンライン時のみ）。期限が印字されていない品は製造年月＋「製造から○年」で期限を自動計算
- 要確認レビュー：写真からの仮登録などを実物と見比べて確定
- オフライン：ホーム画面に追加して、機内モードでも起動・検索
- バックアップ：JSON / CSV の書き出し（オフラインでも可）

## 構成
```
src/
  domain/      在庫の型・検証・期限判定・集計・検索・変更操作（画面にも DB にも依存しない）
  backend/     データの出入り口（本番：Supabase、開発：疑似クラウド）
  local/       端末内（IndexedDB）のスナップショット
  state/       同期とログイン状態の管理（AppController）
  ui/          画面
demo/server.ts 開発用の疑似クラウド（Vite の開発・preview サーバーに載る。本番には入らない）
supabase/      マイグレーション（テーブル・RLS・関数）と CLI 設定
worker/        Cloudflare Worker（静的アセットの配信と、Supabase の休止防止 cron）
scripts/       初期データ投入・アカウント追加・デプロイ・ビルド検査
fixtures/      架空の見本データ（テスト・デモ用）
data/          実データ（gitignore。data/checks/ に実データでの確認テスト）
tests/  e2e/   ユニット（Vitest・PGlite）と E2E（Playwright）
```

## セットアップ
必要なもの：Node.js 22 以上。

```bash
npm ci
npx playwright install chromium
npm run dev
```
`npm run dev` はデモモード（架空の見本データと開発用の疑似クラウド）で起動する。ログイン画面に架空のアカウントが表示される。
本物の初期データをデモで見るときは `DEMO_DATA=data/initial-data.json npm run dev`（パソコンの中だけ）。

テスト：
```bash
npm test             # ユニット（Vitest。DB は PGlite で検証）
npm run test:e2e     # E2E（Playwright。オフライン再起動・2端末同期など）
npm run lint && npm run typecheck
```

本番の Supabase につなぐ場合は `.env.example` を `.env` にコピーして値を入れる（手順は [docs/DEPLOY.md](docs/DEPLOY.md)）。
